# 字体与布局专项审计

本轮仅调整 QML 的字体、行高、间距、尺寸、换行和对齐，沿用上一轮界面加载及播放优化。分支 `native-pip-overlay`，基于 `d6286fcc` 的既有工作区继续，没有提交或发布 GitHub。

## 发现与处理

| 范围 | 发现 | 调整 |
| --- | --- | --- |
| 视频详情的相关推荐 | 固定 `Theme.itemSizeHuge` 行高容不下封面和两行标题、作者、播放量；基线真机大字号截图中，前一行播放量和后一行标题发生压叠 | 行高取封面与文字列实际高度的较大值，再加上下留白；标题/作者/统计字号分层；封面宽度随侧栏宽度限制 |
| 通用内容文字 | 多个页面遗漏用户字号设置，默认字体与已有显式字号混用；长文字缺少边界 | AppLabel 统一内容字号、1.12 倍行高和文本截断；正文保留换行，标题/作者/元数据分别采用适合层级的字号；不改变文字内容 |
| 首页、直播 | 网格行高只依赖固定主题尺寸，大字号会挤压；横屏双列封面撑满首屏，标题被推到屏外 | CardTextMetrics 测量真实字体的两行标题和元数据高度，按测量结果留出空间；横屏采用左图右文，仍尊重单/双列选择；竖屏双列保留上图下文 |
| 搜索、分区、番剧、分集、空间作品、历史/收藏 | 虽然外层高度取文字与图片较大值，文字却仍以固定顶边图片的中心对齐，文字更高时会越出上边距 | 图片和文字均以整个自适应行的中心对齐；补充宽度约束；分集标题允许两行并撑高点击区域 |
| 评论、楼中楼、动态、消息 | 元数据长串可能超宽；消息正文按固定像素裁切，字体变大后容易裁半行；头像与两行作者信息未完全居中 | 元数据按需换行；消息改为完整行数限制；正文与卡片按实际高度布局；作者和头像对齐 |
| 导航、关于、说明页 | 长说明在窄窗口拥挤，导航点击区域未随内容增长；宽屏长段落过宽 | 导航条目按内容撑高、说明最多两行；说明内容在宽屏限制行宽并居中；原生 PageHeader、输入控件继续使用 Silica 的标准布局 |
| 播放器和画质控件 | 字体需要统一，但视频表面、手势和控制逻辑必须稳定 | 仅统一文本表现及画质文字的宽度边界；媒体表面和业务事件处理保持原样 |

`baseline-qml/` 保存修改前的 QML。对比 `native/src/*`、CMake/qmake 文件及全部原生包装文件的 SHA-256，全部保持一致；现有 **221 段 QML 函数/事件处理块**也保持一致。QRC 只新增 AppLabel 和 CardTextMetrics 两个界面组件。该范围检查与真机回归一起使用，不能单靠代码未变就推断所有运行场景均已通过。

## 视觉验收

所有展示图片来自本轮真机新截图，先核对时间戳、PNG 签名和 SHA，再进行视觉检查。基线与修改后相关推荐均使用同一个视频 `BV1P4ddBBEJF`，大字号；另检查了小/中字号和横屏窄侧栏。初始截图工具等待 2 秒偶尔不足，本轮工具改为有限轮询新文件时间戳，拒绝旧图。

大字号竖屏已检查：首页、搜索提示、直播、分区、番剧分类、UP 空间、视频动态、图文动态、评论、楼中楼、历史、导航、关于、显示设置、账户、消息、消息详情、二维码页。小字号检查了首页、直播、评论、推荐；中字号及横屏检查了首页、直播、评论、关于和推荐。字号通过实际设置菜单切换，启动日志分别确认 0/1/2 及其比例 0.92/1.00/1.14。单列首页和横屏单列直播也通过实际菜单切换后检查；收尾已恢复原来的大字号/双列。

横屏双列的初轮截图发现封面过高，随后改为左图右文，最终包截图 `home-final-landscape` 与 `live-final-landscape` 已确认标题、作者和统计信息在首屏可见。相关推荐竖屏和横屏均未见相邻文字压叠；长标题按两行截断，完整标题仍由原有详情入口展示。

搜索接口本轮返回 HTTP 412，已确认错误提示排版正常，未为此更改搜索接口、认证或网络策略；当前真实搜索结果列表的视觉验收受该外部响应限制。未强制模拟迁移占位页、缺少二维码模块等当前设备未触发的状态；这些页面完成源码审计。未提交评论、点赞、退出登录或扫码切换账户。

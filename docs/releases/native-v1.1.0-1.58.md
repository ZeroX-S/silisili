## 自 1.57 以来的完整变更

上一版本：[native-v1.1.0-1.57](https://github.com/ZeroX-S/silisili/releases/tag/native-v1.1.0-1.57)。
[完整源码比较](https://github.com/ZeroX-S/silisili/compare/native-v1.1.0-1.57...native-v1.1.0-1.58)。

### 首页与列表

- 首页卡片改为静止 350ms 后预取播放地址，不再因创建卡片、按压、滑动或恢复
  前台而启动隐藏视频解码。预取最多并发 2 个请求，缓存最多 16 条、有效期 5 分钟。
- 修复解码器启动/取消时访问尚未完成初始化的 codec 的竞态。
- 首页、搜索和直播分页先完成数据、错误和页号更新，再通知加载结束，避免
  快速滚动在中间状态重复分页；失败后可明确刷新恢复。

### 启播与定位

- 普通零秒启播也等待当前文件、起点和首帧纹理确认后再放行音频，修复声音
  已播放而画面仍在等待的问题；加载中按暂停会保留暂停意图。
- 硬解首个目标帧不等待被暂停的音频时钟，避免互相等待。
- 暂停时定位可以解码并显示目标画面，音频继续保持暂停。
- 过滤旧定位序号和旧时间线帧，处理部分适配层在 flush 返回后仍交付旧输出
  的情况，修复从较后位置返回时误显示旧帧、恢复后长时间等待的问题。

### 锁屏媒体控制

- 新增标准 MPRIS 服务，共用现有播放会话，支持锁屏播放/暂停、媒体标题与
  封面信息、停止、点播定位和倍速；与详情页、Cover 和小窗同步状态。
- 直播正确声明不可定位、速率固定为 1；停止播放或退出应用后释放媒体服务。
- Desktop Entry 与安装的 `cn.silisili.native.desktop` 保持一致。

### 二维码与 5.0 实验性兼容

- 保留 5.2 的 Amber.Barcode、5.1 的 QrShareImage 优先级；私有系统组件均
  不可用时，自动使用应用内 QR 编码和绘制，避免空白/黑色二维码区域。
- 新增 5.0 SDK 准备和独立构建入口。5.0 默认采用软件解码，规避旧设备侧
  droidmedia BufferQueue 的兼容问题，并保留明确的硬解诊断开关。

### 构建与测试

- 将实际使用的 VM 构建入口纳入仓库，集成 MPRIS、QR 源码、MOC 与许可证，
  从当前源码生成兼容 shim；源文件/头文件内容和版本变化会使对应对象失效。
- 添加启播检查和真机探针，保留首页、播放同步、锁屏及生命周期验证记录。

## 验证范围与下载说明

- 本附件为 **Sailfish OS 5.1/5.2 AArch64** 开发包，真机验证设备为 Pixel 3a XL /
  Sailfish OS 5.2.0.16；原生开发版继续标记为 prerelease。
- 完整画质矩阵：360P、480P、720P、1080P、1080P60；另验证软解启播、历史
  续播、加载中暂停、暂停前后定位和倍速。
- 发布包 1080P60 横屏连续 60 秒复测，66 个约一秒视频呈现窗口最低 51.74 FPS，
  没有低于 45 FPS 的窗口。该结果仅针对本次视频、设备和测试区间。
- 验证两次前后台往返、Cover、系统小窗拖动、应用内小窗关闭停止播放，
  以及小窗存在时退出应用后的窗口、解码缓冲和 MPRIS 服务回收。
- 实际锁屏截图和物理播放/暂停点击通过；直播画面、暂停恢复及能力声明通过。
- 首页第二页请求失效后，64 次继续分页未卡住，显式刷新在同进程恢复。
- **本标准 RPM 不适用于 5.0。** 5.0 需使用独立 SDK 构建实验包，尚未完成
  5.0 真机回归；本次也不宣称 UHD 硬解或所有设备、账号接口均已验证。

详细记录：[播放与锁屏回归](https://github.com/ZeroX-S/silisili/blob/native-v1.1.0-1.58/docs/playback-validation-20261013.md)。

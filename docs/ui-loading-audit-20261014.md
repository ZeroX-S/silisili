# 界面信息加载审计与优化

本轮在 `native-pip-overlay` 分支 `d6286fcc` 的工作区继续，保留上一轮播放地址选择、首帧门控、定位取消与性能采集改动。没有提交或发布 GitHub 版本。

## 实现

| 页面/路径 | 问题 | 本轮处理 |
| --- | --- | --- |
| 视频详情、评论预览、相关推荐 | 播放稳定后再等待 3/7 秒请求，收到数据后每条再等待 320/420ms；详情按 140ms 分阶段显示 | 详情就绪即请求评论和推荐；直接呈现元数据；预览限制为 4 条评论、6 条推荐，用异步 Loader 分摊创建工作；返回复用在途和已完成请求 |
| 首页推荐/热门 | 翻页触发偏晚、600ms 轮询；重复点分类重新请求 | 统一在距底部一屏时预取；事件驱动、同一事件循环合并通知；分类保存模型、去重集合及页号快照，按账户隔离；显式刷新仍请求新内容 |
| 全部评论、楼中楼、搜索、直播、动态、番剧、个人内容、消息 | 部分只监听到底，短页或旋转后可能没有下一次触发；部分使用 250/700ms 轮询 | 共用 FeedPagination，监听滚动、布局、条数、加载状态及前台状态；只为活动页面预取；保留原模型的游标与串行请求保护 |
| UP 主空间 | QVariantList + Repeater 在追加时重建已有作品/动态，长列表创建无上限 | 改为 QAbstractListModel 按行插入，SilicaListView 只创建视口附近卡片；作品/动态分区、头像、评论入口保留；无进展游标停止；失败流不阻塞另一正常流 |
| 刷新和错误 | 直播、动态、个人内容、番剧刷新先清空；失败后滚动可重复自动重试 | 同一资源刷新保留现有内容，成功后替换；账户/收藏夹/分类改变时隔离旧内容；错误阻止自动重试，保留下拉重试及显式入口；搜索先失效旧请求再取消 |
| 封面、头像、动态配图 | 下载原图再缩小、部分未限制解码尺寸；正常取消也逐条写警告日志 | CDN 请求按 160/320/480/640/960/1280 宽度分档，复用缓存 URL，并设置解码尺寸；签名 URL、已有转换、GIF、其他域名保持原样；只记录真实超时/网络错误，忽略虚拟列表退出视口的正常取消 |

弹幕在首帧就绪后启动。扫码轮询、键盘焦点、手势长按、播放器控制隐藏、画质切换及网络超时计时器有独立业务用途，未按数据延迟计时器一并移除。PGC 详情原本只创建前 6 集，完整分集使用列表页，这条已有的有界创建路径保留。

## 已观察到的结果

固定样本 `BV1P4ddBBEJF` / `37630051884`：旧包 perftest5 在详情创建后约 6 秒发出评论请求、约 10 秒发出推荐请求；评论接口实际耗时约 274ms。优化包首轮评论数据 939ms、推荐数据 880ms 就绪，4+6 张预览卡片全部在 1639ms 内创建完成，视频请求到首帧/音频放行约 1101ms。页面时间从详情实例的 `informationStartedAt` 计时，不包含整个应用冷启动时间，不是网络速度保证。

预览均已收到数据并实际完成 Loader 创建后，才允许输出 compact-restore content ready，避免把“模型有数据”误当作“页面已显示”。

最终 SHA 包在重启后重新验证：`final-ui`（PID 11871）详情 921ms、推荐数据 1274ms、评论数据 1296ms、全部预览 2170ms、播放请求到首帧 1457ms。`final-seek`（PID 20301）1080P60 首帧 1472ms，定位 90/14/120/30 秒依次 2416/1832/2483/2256ms，连续拖动最后目标 201ms；保持同一加载/解码 generation。`matrix`（PID 21826）实际请求及解析的画质为 16/32/64/80/116，首帧门控全部通过。

最终包物理双击小窗返回详情（PID 22617）在同一进程报告：comments=20、related=40、visibleComments=4、visibleRelated=6、commentRequests=1、relatedRequests=1、duplicateRequests=false；实际 Loader 已就绪，并保存 `silisili-validation-final-compact-restored.png`。

最终包网络切换故障注入完成同进程恢复（PID 24867），失败后 64 次继续翻页调用没有形成请求循环，显式刷新后 loading=false、hasMore=true。收尾正常启动 PID 27267，无测试环境变量、空闲 MPRIS=false、`rpm -V` 为空；实际点按推荐/热门往返，分别恢复 28/30 条缓存，最终停留推荐首页并有新截图。

真机日志与新截图已确认：搜索返回 20 条；直播首批 26 条；分区首批 11 条；空间首批 20 个作品、12 条动态并有头像；图文动态首批 14 条；番剧分类往返 8 次及快速跨分类后 `stable=true`；历史首批 20 条。全部评论初始 20 条，物理点击打开楼中楼取得 6 条回复，物理返回后保留原内容，再滑动取得第二页并追加至 26 条主评论（总数 66 包含回复）。首页物理连续滑动取得第二页并追加至 56 条，同一进程且未创建隐藏解码会话。

## 重复验证与边界

在仓库执行：

```sh
node native/tests/ui-loading-smoke.js
node native/tests/home-scroll-smoke.js
node native/tests/playback-start-gate-smoke.js
bash vm-deploy/scripts/verify-silisili-native-source.sh
git diff --check
```

UI smoke 执行实际 CDN URL 策略、详情请求函数和请求去重逻辑；Home smoke 执行实际分页/预取策略。源码验证包含资源与构建输入边界。这些检查不能替代设备触摸/FPS 检查。

把 `vm-deploy/scripts/probe-silisili-native-ui-loading.sh` 复制到设备并运行 `sh ... <唯一运行名>`，可同时验证评论/推荐模型、异步卡片、首帧及单次请求，并保留 `/tmp/silisili-ui-<运行名>.events` 和 `/tmp/silisili-perf-native-<运行名>.log`。定位回归沿用 seek-performance probe，画质/软件路径沿用 play-start probe。

设备在本轮两次更换启动 ID，重启前后分别为 `70375c04-...`、`6c635801-...`、`9d8b48af-...`。用户于 2026-10-14 明确确认，重启由其他调试任务触发，这两次事件不计为 SiliSili 应用故障。没有持久化上一启动 journal，pstore 目录为空；重启来源依据为用户确认。重启后已重新部署临时工具、核对系统和包身份，并独立完成上述最终 SHA 包回归，结果有效。重启会清空 /tmp，后续测试仍须重新核对，不能复用上次临时文件或把脚本失败当作产品失败。

截图核验遇到过测试手势从屏幕边缘触发系统退出，以及 single-instance invoker 未将旧进程带回前台；后续通过桌面实际点开应用、从应用内部发起返回手势，并以页面内容和追加模型日志复核。设备 journal 会丢弃旧条目，已保存的早期日志和后续分页日志应一起阅读，不能要求整个长任务的首批请求始终留在环形缓冲中。

本轮实机覆盖 5.2；5.0 的行为仍须在对应真机确认。收藏、订阅、追番/追剧等共用个人内容路径已审计，历史已实机加载，不等于每个账户下每一种收藏业务均完成实际 API 验证。外部接口失败和弱网仍会增加耗时；已有内容继续可读，失败不会触发自动请求循环。
